Publishing workflow

  1. Editor creates or edits a draft and submits it for review.
  2. Reviewer checks the preview and publishes or rejects the change.
  3. Published content becomes available to the public website after the site is wired to the CMS.

This dashboard manages CMS records. Existing hard-coded page text will not change until the corresponding page elements are connected using data-cms-key attributes (see SETUP.md).

Site settings

Change contact details, office addresses, footer text and the announcement banner. These update on every page of the website as soon as you save. Clear a field and save to go back to the text built into the page.

The enquiry and job-application forms deliver mail to the address written in contact.html and apply.html. That address is not changed from here, so edit those two files if you want to receive mail somewhere else. To make any other piece of text editable, use Website content (every heading and paragraph is already listed there).

Review queue

Reviewers and admins can publish or reject submissions. Editors cannot approve their own changes.

Role assignments

Create users in Supabase Authentication first, then assign a role here. Only an administrator can change roles.

Use admin privileges carefully. Do not give an admin role to people who only need to edit content.
